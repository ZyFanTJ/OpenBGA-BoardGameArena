## 本地运行

Docker 一键运行：`docker compose up -d --build --wait`，打开 <http://127.0.0.1:3100/>。镜像导出、仓库上传和域名 HTTPS 配置见 [Docker 部署](docs/deployment.md)。

需要 Node.js 22.13 或更新版本（使用内置 SQLite）。首次运行先安装锁定依赖，启动时自动构建前端。

```sh
npm ci
npm start
```

打开 http://127.0.0.1:3000 。首次访问直接显示完整游戏大厅；点击「开个房间」，选择桌游类型（CABO / 魔毯商人 / 七大奇迹 / 忍者之夜）、填写昵称和房间名称即可创建，也可直接使用房间码加入。已有对局的身份刷新后会回到原房间。

第二位玩家使用另一个浏览器/独立无痕窗口访问相同地址，输入房间码加入。也可以在本机分别使用 `127.0.0.1:3000` 与 `localhost:3000` 获得两个独立 Cookie 身份。

单人练习：创建房间 → 点击空座位的「添加 AI」（CABO/魔毯商人最多 3 位，七大奇迹最多 6 位）→「我准备好了」→「开始游戏」。AI 自动看起始牌、抽换牌、使用能力和呼叫 CABO；每轮结算后由房主点击「下一轮」。等待阶段房主可移除 AI，再邀请真人加入。七大奇迹至少需要 3 人，可添加 2–6 位 AI；其 AI 自动选面、选牌和处理特殊能力。无需 API Key 或外部模型服务。

```sh
npm ci
npm test
npm run dev
```

大厅和房间大厅使用 React、Radix UI 与 Lucide，通过 esbuild 生成本地浏览器资源。`npm start`、`npm run dev`、`npm test` 会先构建前端；`dev` 同时监听大厅组件和服务端文件变化，页面代码变化后手动刷新。单独构建使用 `npm run build:web`，Docker 镜像构建也包含依赖安装与前端构建。状态按记录写入 `.data/platform.json.sqlite`，重启后保留。首次启动自动导入已有 `.data/platform.json`，原 JSON 和原加密密钥保留；之后以 SQLite 为准。浏览器保留会话 Cookie 时可回到原座位。

房间连续 **5 分钟没有真人在线**会自动回收，每 10 秒检查一次，等待中、进行中和已结束的房间均适用。在线状态采用已认证请求的心跳，75 秒未收到心跳才判离线；前端每 20 秒保活，切到后台也会发送轻量心跳。服务器推送和 AI 行动不算真人保活。任一同桌重新上线会重新计时；服务重启后给已有房间完整的 5 分钟重连宽限。回收会取消待处理邀请及 AI／回合计时／DM 任务，释放座位；已经保存的战绩和奖励保留，未完成对局不会发放完赛奖励。

首页素材使用无损 WebP 和独立封面裁片，桌游界面进入牌桌后按需加载；公共静态文件支持压缩和缓存校验。详见 [性能优化与验证](docs/performance.md)。

默认只监听本机。局域网多人测试可以在 PowerShell 中使用：

```powershell
$env:HOST = '0.0.0.0'
npm start
```

其他设备访问主机局域网 IP 的 3000 端口；系统防火墙须允许对应访问。`PORT` 可修改端口，`DATA_FILE` 指定旧 JSON 导入位置和密钥位置，`DATABASE_FILE` 可另指定 SQLite 路径；默认是 `DATA_FILE` 加 `.sqlite`。HTTPS 反向代理部署时设 `SECURE_COOKIES=1`。只有应用端口不对外开放、所有请求都经过可信代理时，才设置 `TRUSTED_PROXY_HOPS`；随附生产配置仅通过 Caddy 入口，已设为 `1`。直接访问应用保持默认 `0`。

## 目录边界

```text
apps/
  server/              HTTP、静态资源、Cookie、SSE / WebSocket 传输
  web/                 大厅、房间和聊天界面
    games/             游戏专属牌桌渲染器
packages/
  platform/            房间、会话、存储、通用游戏接口
  games/
    registry.js        服务端游戏注册表
    cabo/              CABO 纯规则状态机、视图、计分
    marrakech/         魔毯商人规则、棋盘几何、AI
    seven-wonders/     七大奇迹卡牌、同时选牌、贸易、计分与 AI
tests/                 规则、信息隔离、平台扩展和 HTTP 集成测试
docs/
  architecture.md      模块边界、扩展策略与演进取舍
  adding-a-game.md     新游戏接入步骤
  cabo-rules.md        规则来源与线上边界处理
  protocol.md          API 与并发约定
```

代码采用原生 JavaScript ES Modules，接口另有 TypeScript 声明用于描述边界。该声明不是已启用的静态类型检查。规则函数与网络、文件、DOM 完全分离；随机数由平台注入，生产使用 Node crypto，测试使用固定种子。

## 当前边界

存储适配器是单进程整文件事务，一个数据卷仅供一个实例使用；没有分布式锁、观战或匹配系统。账号支持跨设备恢复，游客清除 Cookie 前需先绑定；当前没有邮箱找回密码。仅断线时保留座位，不自动托管或踢人；主动退出会由 AI 接管。全员解散投票不会把断线当作同意。过期会话在新建会话时清理，战绩与历史房间尚未做容量归档。商城采用对局星辉，不涉及真实货币支付。

平台接口不限定轮流行动，但当前传输和同步面向离散行动桌游；高频实时物理游戏需要不同的同步模型。状态版本不匹配会拒绝行动，应先实现迁移，不自动解释旧存档。

扩展之前先阅读 [架构设计](docs/architecture.md) 和 [新游戏接入](docs/adding-a-game.md)。规则与线上处理细节见 [CABO 规则说明](docs/cabo-rules.md)。

## UNO · 经典 108 张版

支持 2–10 人、AI 陪练、同色/数字/符号出牌、抽一张再决定、跳过、反转、+2、选色、+4 接受与私密质疑、UNO 宣告与抓漏喊、跨轮计分及 500 分整场胜利。100 / 300 分为明确标注的线上短局选项。桌面沿用 CABO 的青绿牌桌、环桌座位与底部私密手牌，提供可出牌提示、手机横向手牌和玩法手卡。

规则版本、官方说明书、版本区别与线上解释见 [UNO 规则](docs/uno-rules.md)；官方媒体素材检索结果与本站原创矢量卡面说明见 [UNO 素材](assets/uno/README.md)。本次未找到可直接使用的完整官方卡面资源包，运行时采用原创 SVG。

组局分享：点击房间顶部或空座位的邀请按钮后打开分享面板，支持复制房间链接、复制微信 / QQ 等群聊邀请文案，以及在支持的浏览器调用系统分享。建房后不自动弹出面板，准备区和聊天侧栏不常驻分享区域；朋友打开链接后，已有昵称且未在其他房间时直接入座，首次访客只需填写昵称。已有座位可通过原链接直接恢复。邀请使用最新房间版本提交，遇到并发变更自动刷新一次；满员、开局或已在其他房间时显示明确提示。
