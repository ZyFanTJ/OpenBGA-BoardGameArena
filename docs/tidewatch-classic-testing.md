## 浏览器操作

用两个独立浏览器身份进入同一房间，验证建造、一级升级、二选一专精、港口扩建、渔市、遗物领取、跨区减速支援、轰击选点、刷新恢复、结算和再次开局。四人房间加入两个 AI，AI 可以完整建造和成长。测试服务重启后从持久化检查点恢复，没有补算停机时间。

新版 UI 删除常驻标题、教程、长解释、重复标签和装饰性文案。详细规则、音效、波次与建筑说明按需打开。桌面采用地图与操作侧栏，手机采用纵向地图和底部操作区。画布随竖屏高度变化，塔与怪物图像保持比例；射程和命中区同步适配。

## 压力记录与边界

本机 Node + SQLite，400 个怪物、48 座塔，每次 4 个 50ms 子步、4 个玩家投影，采样 100 次：

| 测量 | P50 | P95 | 最大 |
| --- | --- | --- | --- |
| 规则 + 投影 + JSON | 7.69ms | 10.58ms | 15.00ms |
| SQLite WAL / FULL 提交及投影 | 47.66ms | 73.03ms | 96.87ms |

压力投影约 69,732 字节；当前全量投影每秒 5 次，在该人工压力下约 349KB/s/玩家。尚未做增量协议，不能将本机结果直接外推为大规模并发或弱网性能承诺。

前台桌面浏览器、400 个敌人集中同屏、48 座全图建筑的绘制夹具，预热后采样 1,800 个实际场景帧：平均 16.67ms，P95 23.00ms，超过 33ms 的帧为 1 个。目标帧率限制为 60，瞬时特效最多 120 个。后台标签页限帧数据不计入。

响应式尺寸检查不等于真实手机 GPU、触屏延迟和移动网络实测；上线前仍应在目标 iOS/Android 设备上检查耗电、加载时间及热降频。Docker 配置已补齐运行时 WebSocket 依赖，但本轮未构建容器或部署线上。
