# 好友、战绩与月辉秘藏

## 信息与操作

大厅导航统一提供好友、战绩、商城与个人档案。界面以深墨蓝、暖金和高对比文字组织信息，插画承载氛围，操作不写进插画。桌面使用主内容与侧栏；手机优先保留主操作和列表，次要说明向后放。

- 我的房间：已有房间时直接返回自己的牌桌；没有房间时展示公开房间大厅。支持房间名、房间码、房主、桌游名称搜索，与桌游、可加入 / 全部 / 进行中组合筛选。每页 12 间，手动刷新保留筛选，空闲时约 30 秒自动刷新。私人房间不进入列表，满员或已开局房间不能加入。退出或解散后回到房间大厅。首页仅保留已知房间码的快捷加入。
- 好友：好友码或账号前缀搜索 → 申请 → 对方接受 → 创建房间 / 邀请 → 对方加入。在线状态约 20 秒刷新，75 秒无活动显示离线。邀请 10 分钟有效；接收时重新检查好友关系、发起者成员资格、房间人数与版本。
- 战绩：总对局、胜场、胜率 → 单场胜负、名次与得分 → 点开最终排名、各项计分与星辉。支持桌游、胜负、真人 / AI 筛选与分页。
- 商城：浏览头像 / 名片背景 / 称号 → 查看自己的装备预览、价格和兑换后余额 → 确认兑换 → 装备。已拥有与已装备状态独立，不会重复收费。
- 档案：全幅个人背景与头像身份区，配合真实对局概览、旅程徽章、主打桌游、最多 4 件有序藏品和最近战绩；侧栏集中同桌好友、钱包与账号。编辑采用基本资料 / 头像与背景 / 藏品陈列三组，支持 160 字简介、主打桌游、已拥有外观、展位顺序和实时预览。游客绑定账号后保留原资料。
- 好友资料：从好友名片或个人资料侧栏进入，只能读取已接受好友关系且允许好友可见的资料。可设置仅自己可见；钱包、完整库存、账号与其他玩家的战报数据均不发送给访问者。未登录无法读取资料。
- 资料统计：完成场次和胜率排除中途离席，显示真人 / AI 练习数量；主打桌游支持手动选择，未选择时按实际完成场次选常玩桌游，零对局不伪造游戏或胜率。徽章来自真实完成场次、胜场、库存与好友数，不新增虚构等级或经验值。

## 经济与记录

这是对局星辉兑换的外观商城，没有接入真实货币支付。首次创建身份赠送 300 星辉。真人对局完成奖励 40、胜利奖励 70；有预设 AI 的对局视为练习，完成 20、胜利 30。数额是最终本场奖励，不叠加。并列胜者均获胜利奖励；中途离席、未完成或投票解散没有奖励。

价格以服务端目录为准。钱包、藏品、装备共享资料版本；兑换使用幂等请求标识，扣款与收支记录同事务提交。奖励以对局与玩家组成唯一键。客户端不能提交得分、奖励或商品价格。

记录在最后一步游戏行动的同一事务中生成，仅保存已公开的终局摘要，不保存完整牌库、手牌或聊天。游戏通过可选 `result(state)` 适配器提供结果；没有该适配器的插件仍可玩，但不产生战绩。已经结束的旧房间会补录摘要，时间标记为“历史存档”，不追发奖励。

## 数据与账号

存储格式当前为 7。v1 → v2 建立账号、好友与经济索引；v2 → v3 为 profiles 增加 details（bio、favoriteGame、visibility、showcase）。迁移分别保留 `.v1.bak` / `.v2.bak`，不覆盖已有备份。后续 v3 → v4 为房间补固定座位，v4 → v5 增加论坛，v5 → v6 增加系统设置及管理员权限与审计；v6 → v7 增加房间操作时限与时钟，旧房间保持不限时；各阶段通过存储所有者模块迁移。默认好友可见、简介为空，展位沿用已拥有的当前装备。会话、余额、库存、战绩与游戏状态保持不变；各游戏 stateVersion 不变。

密码使用随机盐与 scrypt 派生，Cookie 为 HttpOnly / SameSite=Strict，有效 30 天，服务端只保存会话摘要。公开名片不包含钱包、库存、密码派生值或私人房间码。战报仅本人参与的对局可读。当前未提供邮箱找回密码；游客清除 Cookie 前请先绑定账号。

## 原创美术

使用内置 imagegen 生成三幅场景和六角色头像图集。场景、角色和金属 UI 边框保持同一冷蓝暖金色调；文本、价格与按钮由真实界面绘制。

- 可部署素材：`apps/web/assets/hub/*-v1.webp`，四张总计约 1.59 MB。
- 可复用提示词：[prompts.json](../assets/hub/prompts.json)。
- 尺寸、文件摘要与生成方式：[manifest.json](../assets/hub/manifest.json)。
- 头像图集为 3 × 2，依次银狼、雪鸮、灵狐、古龙、守卫、贤者。

## 验证

`npm test` 覆盖迁移、账号、密码与会话、好友权限、邀请事务与过期、兑换幂等与版本、三个游戏的完整对局归档及去重奖励。浏览器验证覆盖双账号申请 / 接受 / 邀请加入、兑换装备和刷新、真实三人七大奇迹战绩、计分明细、手机布局与重新登录。浏览器生成的数据与截图仅在忽略的 `work/` 下。

资料更新通过 POST /api/profile 在同一事务校验资料 revision、外观所有权、展位数量及桌游有效性，再原子保存。旧版本冲突保留编辑草稿，并提供明确的重新载入操作。

## 社区页面的共同头部

论坛、好友、战绩和商城共用 `apps/web/page-header.js`，页面框架与断点统一使用 `hub.css`。各页只提供标题、简短副标题、插画和操作内容；操作区保留统一高度，手机副标题预留两行。导航始终挂载，非搜索页面仅隐藏搜索内容并保留位置。论坛的话题侧栏、筛选、列表和讨论详情继续由论坛模块负责。
