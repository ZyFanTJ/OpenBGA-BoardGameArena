# CABO 动作设计

`cabo-motion.js` 是游戏界面独立的展示层，使用浏览器 Web Animations API。`cabo.js` 保留选择和命令处理，`cabo-table.js` 提供有稳定牌位锚点的静态画面。平台通过可选的 renderer.update/dispose 生命周期接入，不理解卡牌动作。

## 动作节奏

| 操作 | 过程 |
| --- | --- |
| 发牌 | 从牌库逐张飞向各座位，错开 24ms |
| 抽牌 | 从来源牌堆抬起、弧线移动、私密翻面，约 580ms |
| 弃牌 / 发动技能 | 手牌飞入弃牌堆并落牌，技能出现短暂的 PEEK/SPY/SWAP 提示，约 560–620ms |
| 换牌成功 | 旧牌先翻出并进入弃牌堆，新牌补位，其余牌平移收拢，约 880ms；多牌略微错开 |
| 换牌失败 | 原牌按规则翻开，手持牌补到指定端，惩罚牌从牌库随后加入 |
| PEEK / SPY | 目标光环、抬起和翻面；确认后盖回。其他人只看见背面动作 |
| SWAP | 先用双色光环标记两个牌位 350ms，再沿错开的弧线交换 1200ms；落牌后保留光环与「交换完成 · 留意新的牌位」提示 700ms，总计约 2250ms |
| CABO / 结算 | 呼叫提示；最后回合结束后逐张公开结算牌 |

中央牌堆预留手持位，抽牌时不会改变已有牌堆的位置。移动卡牌使用独立浮层，避免牌列透视或滚动区域裁掉飞行轨迹。翻面使用两面结构和背面隐藏，移动有抬升、阴影变化、减速落牌与轻微回弹。

## 同步与恢复

- 按 revision 串行播放服务端快照；同一动作的 HTTP/SSE 重复通知不会重播，旧响应被忽略。
- 动作期间牌桌暂时不可点击，聊天和房间工具不受影响。完成后恢复焦点及操作。
- 积压时缩短动作，SWAP 保留完整观察时间；严重积压、丢失中间 revision 或后台页面直接显示最新权威状态，不猜测遗漏动作。
- 窗口变化、滚动、页面隐藏和组件销毁会取消当前浮层，解除隐藏和锁定。
- 系统启用“减少动态效果”时直接切换状态；SWAP 仅显示 1800ms 静态完成提醒，CABO 保留静态呼叫提示。刷新/重连没有动作提示，因此不重播。
- 动作提示和动画记忆都不进入游戏存档。卡面严格来自当前玩家可见的数据，未获准的牌值不会写入 DOM。

## 响应式牌桌与玩法手卡

- 房间顶部将桌名、昵称、连接状态、房间码和聊天合并为一栏。
- 手机端将对手集中在上方，中央突出牌库、弃牌和抽到的牌；自己的手牌与操作区放在下方。主操作按钮至少 44px 高，额外手牌可横向滑动。
- SPY / SWAP 选目标时，对手手牌展开为独立点击区域；短屏缩小此时不可操作的中央牌堆。
- 桌面端右侧常驻 CABO 玩法手卡；手机端右上角入口打开底部弹层，支持关闭按钮和 Escape。手卡不会随牌局推送重新创建，阅读时 AI 可以继续行动。
- 手卡由 CABO UI 模块维护，内容依据当前 2019 第二版实现，并根据专家模式展示公开牌提示。
