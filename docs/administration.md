# 管理中心

## AI DM 服务配置（0.7.0）

使用管理员账号打开「管理中心 → AI DM」（`/#admin/ai`），填写 OpenAI 兼容服务的 HTTPS 基础地址、模型名称和 API 密钥，启用后保存。修改会在后续模型请求中生效，无需重启；已经发出的请求按原配置完成。没有配置、未启用或服务出错时，跑团继续使用明确标注的本地引导。

密钥输入框不会回显原值；留空保留已保存密钥，输入新值替换，也可关闭服务并勾选清除。管理操作校验权限和配置 revision，并支持请求重放去重。审计只记录配置状态与替换/清除动作，不记录密钥。

`GET /api/admin/ai` 仅返回配置及是否已有密钥，`POST /api/admin/ai` 保存设置；游客、普通用户和跨来源写入均被拒绝。密钥在存档内使用 AES-256-GCM 加密，独立随机加密密钥保存于 `platform.json.secrets.key`，权限 0600，与存档一起处于服务器数据卷内。备份必须包含整个数据卷；恢复时同时恢复 JSON 和加密密钥文件。环境变量仍可用于首次配置前的兼容启动，首次后台保存后以后台配置为准。

平台存储 v7 → v8 只增加独立的模型服务配置，原房间 revision、游戏状态、账号、会话、资产、论坛和审计不改变，原始文件保留 `.v7.bak`。回滚到旧镜像时先停止服务并恢复升级前完整数据卷。

后续 v8 → v9 为模型配置补入上下文、温度和 DM 风格字段，保留旧服务地址、模型、加密密钥、配置 revision 和房间状态，并自动备份原始 v8 文件。

### 上下文、温度与 DM 风格

在「管理中心 → AI DM」中独立编辑：

- `contextTokens`：默认 **100,000（100k）**，允许 4,096–1,000,000。它是输入历史加输出预留的应用预算，不是单次回复长度，也不能扩大服务商的模型窗口。服务端始终保留系统规则和当前局势，再从最近记录向前加入历史；超预算时按整条记录裁剪，不修改存档。
- `temperature`：默认 1，支持 0–2。留空保存为 `null`，请求不发送该参数，适合要求使用模型默认值的兼容服务。
- `dmStylePrompt`：独立的叙事/人物扮演提示词，最多 1,000 字。可设置黑暗童话、幽默、紧凑节奏、环境描写等；留空不附加风格。只有带 DM 风格标识的请求使用它，其他通用模型任务不受影响。它不替换游戏的规则与输出格式约束。

配置对下一次请求生效；修改这些字段不需要重新填写现有 API 密钥。保存仍使用 revision、requestId 与操作备注，审计不包含明文密钥。较早客户端省略新增字段时保留已有值。

通用兼容服务没有统一分词器，因此当前用 UTF-8 字节数作为保守的 token 上界，并预留 900 输出 token 与消息开销；可能比具体模型的实际可用窗口更早裁剪。若仅当前必要信息就超出预算，请求不会发出，游戏使用本地接续。参数语义参考 [OpenAI Docs 的 Chat Completions 说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

入口为 `/#admin`。已授权账号登录后，顶部“管理”和手机端“更多 → 管理中心”可直接进入。普通用户、游客和未登录访问者均无法读取管理数据或提交管理命令。

## 首位管理员

先在正常登录页面注册或绑定一个账号，再通过服务端启动配置指定它的登录名：

```env
ADMIN_BOOTSTRAP_HANDLE=your_registered_handle
```

Docker Compose 从项目 `.env` 读取该值并传入应用；原生启动读取同名环境变量。配置的必须是已存在的注册账号，不使用默认管理员密码，不把任意游客或第一个注册者自动升级。首位管理员绑定完成后可清空该配置。已有可用管理员时，此配置不会再次提权其他账号；后续授权和撤销由后台完成。

配置应用重启前需要保留原持久数据卷。账号登录名不等于 SSH 用户名，绑定只影响指定账号的管理权限，不改变星辉、藏品、房间和游戏进度。

## 页面与权限

- 运行总览显示真实用户数、注册与在线人数、当前房间及对局数、余额总量、最近用户和管理操作。
- 用户管理支持昵称、账号、好友码、用户 ID 搜索，注册/游客/管理员/在线/停用筛选，加入时间、访问时间或星辉排序，每页 20 人。档案显示账号和个人资料、好友/藏品数、所在房间、有效会话数、最近收支与战绩；不会返回密码摘要、盐、Cookie、会话令牌或秘密游戏状态。
- 资料修正可修改昵称和简介；保留登录账号、用户 ID、隐私范围、藏品和房间归属。修改昵称后房间和好友使用最新资料，历史聊天和比赛记录保留原有记录。
- 星辉支持设置为目标余额，或用正负数增加/扣减。预览修改后余额；备注必填，余额不得为负。调整同时写入资产流水和管理审计，用户自己的账簿显示“管理员调整”。
- 账号支持停用/恢复、撤销所有设备会话、为注册用户授予或撤销管理员角色。停用立即撤销会话并阻止登录，房间座位保留。不能停用自己或撤销自己的管理权限；至少保留一位可用管理员。恢复后需重新登录，原 Cookie 不恢复。
- 操作记录按时间分页，可搜索操作人、目标、备注，展开查看修改前后的真实值。应用接口不提供删除审计的操作。

## 系统设置

### 游戏逐项上线

「管理中心 → 系统设置 → 游戏上线」列出所有已安装游戏，各自保存上线开关，包含德州扑克。保存后当前页面立即更新，其他打开的页面约 30 秒同步公共配置；无需重启。普通用户无管理写入权限。

下线会隐藏大厅卡片和创建选项，服务器在事务内拒绝创建该游戏房间、加入未开局房间及开始新对局。已在房间的玩家可以恢复连接或离开；已经开始的整场比赛（含下一手/下一轮）继续进行，正常保存战绩。终局后可返回等待室，但重新开局必须等游戏重新上线。新旧房间和玩家资产不会被清除。

配置保存于既有 `system.settings.gameAvailability` 可选映射，键是已注册游戏 ID，值是布尔值。缺失条目默认上线，旧 v9 存档无需改写，原游戏状态及 stateVersion 均不改变。旧客户端省略该字段时保留已保存映射；未注册游戏 ID、非布尔值及过期 revision 均被拒绝。保存沿用系统设置的管理员复核、事务、requestId 幂等与变更审计。

`GET /api/games` 保留全部已注册元信息并增加 `enabled`，供现有下线房间继续解析标题和人数；玩家大厅与创建表单只展示上线项。`GET /api/system` 提供公开的 `gameAvailability`；`GET /api/admin/settings` 附带可配置游戏列表。游戏注册表通过参数注入平台，平台不导入具体游戏规则。

站点名称与公告面向所有玩家，公告留空时隐藏。当前浏览器保存后立即更新，其他已打开页面在约 30 秒内刷新公共设置。

注册、游客入座、创建房间、商城兑换、论坛发帖与回复均有独立开关，由对应领域服务在提交事务内执行。关闭新用户或创建房间不影响现有身份、登录与已有对局；关闭商城兑换仍可装备已有藏品，关闭论坛发帖仍可阅读已有话题。

首次入座赠礼、AI 练习胜利/完成、真人对局胜利/完成的星辉发放可分别设置为 0–100000 的整数。注册绑定不会再次发赠礼；设置只影响今后的新赠礼和对局结算，不重算旧记录或改动已有余额。终局奖励仍按 matchId 和用户去重，中途离席不领奖。

保存设置需要当前设置 revision 和备注；有更新冲突时保持输入并提示重新载入，不覆盖别人的修改。

## 数据和接口

平台存储 v5 → v6 新增 `system` 与 `administration`，默认配置维持原功能和星辉发放。v4 存档先经过论坛 v5 迁移。原文件以其原版本备份，例如 `.v4.bak` 或 `.v5.bak`。游戏内部状态与各游戏状态版本不变；旧镜像不能直接读取 v6，回滚需停止服务并恢复升级前备份。

管理接口使用正常登录会话，并在服务端每次检查注册身份、管理员角色和停用状态；写入事务内再次校验权限。资产/资料修改校验 profile revision，权限修改校验 accessRevision，系统设置校验独立 revision。所有管理写入包含备注和 requestId，同一操作重放不会重复入账或生成重复审计；不同内容不能复用请求标识。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/system` | 公开名称、公告和功能开放状态，不含管理信息 |
| GET | `/api/admin/overview` | 运行总览 |
| GET | `/api/admin/users?q=&filter=&sort=&page=` | 用户分页 |
| GET | `/api/admin/users/:id` | 用户档案 |
| POST | `/api/admin/users/:id/profile` | 修正昵称与简介 |
| POST | `/api/admin/users/:id/credits` | 设置或增减星辉 |
| POST | `/api/admin/users/:id/access` | 权限、停用和会话管理 |
| GET / POST | `/api/admin/settings` | 查看与保存系统设置 |
| GET | `/api/admin/audit?q=&page=` | 操作记录 |

后台沿用应用的同源检查、JSON 内容类型校验、请求大小上限、限速和防止内联脚本执行的 CSP。测试数据与截图仅保存于忽略的 `work/admin-system/`。

## 本次验证

0.5.0 本地镜像构建通过 174 项测试。管理专项覆盖权限绕过、敏感字段投影、分页筛选、星辉与购买的版本冲突、重复请求、权限授权、停用与撤销会话、系统开关及奖励规则、审计、v5 原始备份与纯迁移。实际浏览器经过登录、查看和修正资料、调整星辉、并发修改冲突、授权、停用恢复、保存设置与公告，以及 320/390/768/1280/1440/1920px 布局。最终 Docker 提供的后台资源与源码校验一致，未登录管理接口为 401。

本地从旧存档升级后，8 个房间的全部游戏内部状态、8 份玩家资料、账号、会话、好友、邀请、战绩和资产逐项比对保持一致。根据用户指定，2026-10-20 将已注册账号 `zyfan` 绑定为首位管理员；绑定前后完整存档比对仅新增该账号的管理员权限与一条初始化审计记录。临时启动绑定配置已移除，服务重启后权限保留，未登录管理接口仍返回 401。上述绑定先在本地完成；随后随 0.5.1 更新，云端同名既有注册账号也已绑定，备份与存档迁移验证见 `docs/remote-deployment.md`。

## 热门游戏

在「系统设置 → 游戏管理」中为游戏开启 Hot。首页会将已上线的 Hot 游戏排在前面，并在封面左上角显示角标；多个 Hot 游戏保持原有相对顺序。Hot 与上线开关独立保存，设置受管理员权限、版本校验和操作记录保护。
