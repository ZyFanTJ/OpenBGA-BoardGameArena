# 雾灯纪行：沉浸式跑团玩法设计

更新于 2026-10-20。本文区分已经可以玩的功能和完整战役的后续设计；服务部署、模型协议、成本与故障恢复见 [总体方案](dnd-plan.md)，规则版本和房规见 [规则说明](dnd-rules.md)。

## 设计依据

玩家应能理解自己正在尝试什么、角色为何擅长、要付出什么、选择改变了哪里。由规则、世界和内容系统保证这些事实，AI 以 DM 的口吻表达它们。

[Larian 的 Active Roll 介绍](https://forums.larian.com/ubbthreads.php?Number=779588&ubb=showflat)强调投骰前使用加值、法术和优势参与决策，也介绍了逐层查看规则的界面。这篇 2021 年开发公告在此作为交互设计来源，不作为当前 BG3 所有机制的规范。[探索与和平路线设计说明](https://baldursgate3.game/news/community-update-11-inspiration-freedom-pacifism_17)则支持为多种解题方式提供内容反馈。

本项目采用这些设计思想，视觉、故事与代码均为原创。BG3 的灵感重掷、职业调整和电子游戏改编不会自动成为本项目规则；基础规则锁定 SRD 5.2.1，差异明确记录。

## 一次有参与感的判定

1. **选择前**：紧凑行动栏只显示图标、行动名、成功率或资源成本，属性、技能、DC/AC 和完整公式在判定面板展示。成功率由规则枚举骰点计算，攻击包含自然 1/20，优势按两骰取高；只表示当前判定，不预测任务胜负。无风险动作直接进行。
2. **投骰前**：服务器锁定合法行动，打开专注面板。玩家看清属性分、调整值、熟练加值及难度，再亲手点击。取消不消耗回合、药水、生命骰或法术位。
3. **投骰时**：原创 SVG 骰面配合旋转、弹起、光晕和滚动数字；普通 d20 一枚、优势两枚。动画约 1.25 秒，系统减少动态效果偏好会跳过旋转。动画只呈现服务器保存的结果。
4. **揭晓后**：展示最终骰点、加值、总数与成败。伤害、治疗和场景后果进入独立规则日志。重复请求因 revision 冲突被拒绝；刷新不会重新掷骰。
5. **故事继续**：地图、目标和角色同步规则事实，AI 再叙述后果。玩家可以先查看结果，无需等模型回复才知道骰点。多人看到同一结果，动画播放速度不影响回合。

以上已实现。临时引导术、同伴帮助、灵感重掷尚未实现；加入前要有资源字段、使用时机、施法者授权和事务验证。BG3 式灵感如被采纳，应作为明确的房规配置。伤害骰当前在规则结果中展开，尚未使用独立的第二段伤害动画。

## 地图的三个层次

| 层次 | 回答的问题 | 当前实现与后续范围 |
| --- | --- | --- |
| 冒险区域图 | 我在哪里，去过哪里，知道哪些路线？ | 已实现四节点路线图、当前位置、探索迷雾和水渠线索。后续支持可往返的分支区域 |
| 场景与交互物 | 眼前有什么，能对谁做什么？ | 已实现三套剧本共 23 张原创像素风场景、人物/敌人透明立绘、物件热点、上下文行动筛选及状态面板；尚无自由移动和距离规则 |
| 战术地图 | 能走到哪里、打到谁，哪里有掩体？ | 尚未实现。需位置、移动预算、射程、视线、掩体、遮挡和机会攻击 |

现有路线图由服务器场景、线索和进度确定。未探索地点的名称不投影给客户端，任务列表也不提前揭示。当前没有自由寻路和战术移动。完整地图需要先有空间规则和可交互实体，再让美术表达这些规则。

## AI 之外的状态所有权

| 系统 | 必须维护的事实 | 本次实现 | 完整战役扩展 |
| --- | --- | --- | --- |
| 角色 | 属性、HP/AC、装备、法术、消耗与死亡状态 | `players[].character`、四种原型、角色面板 | 等级、职业特性、技能选择、背包、条件、专注与恢复 |
| 世界 | 区域、门与机关、可见性、NPC 状态 | `scene / clues / attempted / combat` 推导地图和实体 | 有稳定 ID 的区域图、实体状态表、阵营关系、昼夜 |
| 任务 | 目标、触发条件、分支与结局 | 场景、线索和 `outcome` 推导目标清单 | 任务图、跨任务依赖、多结局与失败后续任务 |
| 规则 | 合法动作、目标、DC、骰点、伤害、资源 | 纯规则函数、`pendingCheck / lastCheck`、先攻与回合 | 空间规则、附赠动作、反应、效果组合 |
| 内容 | 场景描述、NPC、行动条件、后果 | `content.js` 原创冒险数据 | 独立版本内容包、来源记录、编辑校验、分支可达性检查 |
| 记录 | 已发生事件、存档版本、待处理行动 | 最近 100 条日志、持久化快照、v1→v2 迁移 | 完整事件存储、章节摘要与可回放战报 |
| AI DM | 描述公开事实、理解意图、扮演 NPC | 过滤后的只读上下文；受限行动提案或叙述 | 人物语气、情绪及记忆摘要，仍无直接改存档权限 |

短篇通过派生视图维护地图与任务，避免两份可写状态互相矛盾。长期战役增加实体数据时，需要提升存档版本并迁移。门是否打开、药水是否喝过不依靠 AI 回忆聊天。

```mermaid
flowchart LR
  A[玩家意图与行动] --> B[合法动作与规则校验]
  B --> C[判定预览与主动掷骰]
  C --> D[保存世界、任务、角色变化]
  D --> E[玩家可见地图、状态与日志]
  D --> F[公开事实上下文]
  F --> G[AI DM 叙述后果]
  G --> E
```

自由文字可以由 AI 提出新的检定、故事变化和支线，沿用已有障碍效果或通过有限的环境影响产生优势/劣势。服务器校验结构、技能、难度、前提与后果；需要检定的提议先交给玩家确认，不执行额外状态写入。模型叙述依旧可能出现文字幻觉，独立规则结果和状态面板保持可查。

## 内容与参与感

每个重要障碍提供至少两种解法：能力检定、已有线索、资源投入、战斗或改道。失败带来可理解的代价或新局面。当前矿门有游说、调查、力量和战斗四条路径；仪式失败会触发最终遭遇。一次检定失败后仍能尝试其他途径，但不能无限重复同一检定。

内容包下一步建议采用稳定 ID 的节点：`场景 → 可交互实体 → 行动条件 → 判定 → 成功/失败效果 → 后续节点`。每项效果采用规则白名单；内容编辑器检查缺失引用、不可达结局、必经死锁、重复奖励、版本和许可。AI 可以丰富台词与感官描述，不能临时发明必需的钥匙或删掉一条既定路线。

角色背景目前作为个人笔记保存，只有本人可见。个人剧情需要玩家明确选择公开或与 DM 分享的片段，再增加背景目标和触发条件；不能把“私密背景”默默发给模型。

## 界面与反馈

主界面采用「场景 + 叙述字幕 + 行动栏 + 队伍状态」。顶部只留当前位置与目标，人物和物件通过热点进入相关动作；底部用职业徽记和生命条表达队伍状况。地图、任务、六属性、库存与日志移到工具栏面板，规则解释按需展开。

行动栏默认最多五项，以图标、短名称和一个关键数值区分；资源恢复放在药水按钮，其余操作放在更多行动。属性拆分进入检定面板后展示。计算记录保留在日志，可点击最近骰点重看。手机单列展示场景与字幕，行动栏横向浏览；面板使用原生对话框管理键盘焦点。

战斗时呈现 HP、敌人、先攻与资源。后续战棋版需清楚显示目标、移动路径、预计命中、伤害骰、条件持续时间，以及动作/附赠动作/反应消耗。多名敌人的快速结算应排入可回看事件队列，玩家的关键检定保留仪式感。

音效、语音和立绘尚未加入。以后声音需要独立开关；资源加载失败不阻塞行动。动画和声音不泄露未发现目标，减少动态效果模式保持功能完整。

## 流式 DM 与打字机效果

叙述使用真实 `stream: true`；意图识别仍等待完整 JSON 校验，片段不能触发行动。服务端增量解码 SSE、UTF-8 和 JSON 字符串，只提取 narration 文本。网关若返回普通 JSON 仍可使用完整结果。

片段只在内存维护，通过对局 ID、请求 ID 与请求指纹验证后，最多约每 80 毫秒推送一次，依旧经过游戏的逐玩家 view。重连可读取当前片段；服务重启按持久化 pending 重新请求。完整响应通过校验后一次性保存，中断或无效响应使用本地完整叙述替换片段。

前端独立维护显示位置，以动画帧平滑输出，积压时加速。增量只更新字幕，不重建场景、输入框或打开的面板。最终保存时延续显示进度，刷新不重播历史。减少动态效果偏好会直接显示已经到达的文字。字幕限制可视高度，长内容可滚动或展开；打字机不会消除模型首字前的等待。

## 多人决策与扩展顺序

自由行动现在支持独立检定、改变当前障碍的解决办法、一次性环境优势/劣势，以及可继续追踪的衍生支线。裁定面板显示技能加值、DC、理由和成败风险；掷骰前可以取消。主界面只新增一个小型故事入口，有实际环境影响时用短标签提示，详细记忆与支线按需打开，避免再把解释铺满画面。规则边界与记忆容量见 [自由行动规则](dnd-rules.md#自由行动与故事后果)。

当前探索按座位轮流、战斗按先攻，允许主动让过。下一阶段加入队伍路线投票、发言人切换、由适合者执行技能检定，以及经过施法者同意的协助。任何玩家的自然语言都不能直接花掉队友的法术位。

建议依次交付：场景热点与更多分支 → 队伍协作与完整一级角色 → 空间规则和战棋 → 跨会话战役、升级与内容编辑器 → 语音与更多视觉表现。每次交付都保持一个可从开局玩到结局的冒险，不用零散功能替代完整游玩。

验收重点是玩家首次进入能找到目标、选择前理解判定及代价、失败后有后续选择、队友能参与、恢复后世界一致。首次行动耗时、澄清次数、分支选择率和弃局点需要真实试玩测量，当前没有把这些指标假定为已达成。

## 剧本美术

三套副本使用独立场景背景，四个职业原型有全身像与头像，NPC、敌人及任务物品由当前玩家视图决定是否显示。原始图集、提示词、压缩文件与校验清单见 [美术说明](../assets/dnd/README.md)。网页素材总计约 3.9 MB，按场景加载。
